## §A — Approach (chosen, with rejected alternatives)

Three options were on the table from the brief. Option C (remove
namespace substitution) is explicitly out of scope per §13
("do not redesign the canonical protocol"), so the choice was
between (A) explicit placeholders `{{MPM_TOOL:mpm_X}}` and (B)
minimal tool-reference markers. **Chose a third path**: a
renderer-side heuristic — per-sentence action-context check — that
reads the existing structural separation in the canonical block
(every invocation has `action` in its sentence; every prose mention
does not) without imposing new marker syntax or a templating
framework.

**Why the heuristic is the smallest architecture-fitting fix:**

- The canonical block already separates prose from invocations
  structurally. The heuristic reads that existing structure rather
  than imposing new marker syntax.
- No content rewrites of `MPM_AGENT_INTEGRATION_SNIPPETS.md` are
  architecturally required (the §5 prose-mention alignment was a
  content realignment forced by the renderer correction, not a
  rewording — the canonical block already had bare `mpm_work`;
  only the Claude / Hermes copy/paste examples had stale prefixes
  that needed to be brought in line with the canonical block).
- No marker syntax, no framework, no protocol redesign.
- ~25 lines of renderer code; one regex replaced, one heuristic
  added.

**Plan-agent critique incorporated:** the initial draft was
paragraph-scope; refinement to per-sentence scope adapts to
sentence boundaries, prevents false-positives when prose precedes
an invocation in the same paragraph, and handles the §4
line-wrap case (`mpm_handoff` on line 530, `action` on 531)
cleanly.
