## Remaining Risks

These are the items that require **operator decision or larger design
work** before automatic fix is appropriate.

### 1. `restore-db` SQL primitive (C-2)

`tx.Exec(string(content))` runs the dump as one statement. A safer alternative
is a strict allow-list parser:

- `INSERT INTO memories/topics/lessons/...` (allow)
- `CREATE TABLE X IF NOT EXISTS (...)` (allow, but only if X is a known table)
- `ATTACH`, `DETACH`, `CREATE VIRTUAL TABLE`, `PRAGMA` (deny)
- bare `SELECT` from internal tables (deny)

This is a substantial design decision because the current dump format
includes `CREATE INDEX`, `CREATE TABLE`, `INSERT`, and `BEGIN`/`COMMIT`
statements — a strict allow-list needs to enumerate them all.

**Recommendation:** schedule as a focused task with a security-engineer
reviewer. Estimated 1-2 days of work.

### 2. CSRF token rotation (FE-4)

The current model — per-server constant — is correct for a same-origin SPA.
The risk surfaces only when:
- `--allow-anonymous` is enabled AND
- a future change sets permissive CORS AND
- the operator accidentally opens the SPA on an attacker-reachable network

Mitigation options:
- Issue a token at login (no login flow today; would require auth refactor)
- Tie the token to a session cookie with `SameSite=Strict`
- Drop the CSRF layer entirely (the Bearer token is the only thing it ever
  actually defended)

### 3. Shred dangling singleton (H-2)

Needs a refactor of `dbManagerOnce sync.Once` into a guarded mutex +
condvar pattern so the singleton can be reset. Low practical impact.

### 4. Shred cron / shred in-flight writes (H-4)

Needs `flock(dbPath)` and a daemon-quiescence check. Larger change.

### 5. Drift web/ directory (FE-1)

Tracked in git. `git rm -r web/` is the fix; it is **not** served by the
binary so there is no live exploit, but the maintenance hazard is real.

### 6. Cursor-based pagination (H-7), unbounded fires (H-5),
unbounded JSONL reads (H-12)

All performance/reliability fixes that are isolated but each requires
its own test. Not auto-fixed because the API contracts would change.

### 7. `audit.md` path drift (CFG-03, NEW-02)

The 2026-07-07 audit's references to `internal/...` are stale. Update path
prefixes to `internal/core/...`. The audit was scored against a different
working tree; new patches (this pass) need to be folded into a follow-up
audit pass.

### 8. `Makefile` `go 1.26.1` toolchain pin (DEP-01)

`go.mod` says `go 1.26.1`. This is either a real release or an unreleased
toolchain depending on your distribution. **Verify and update before the
release cut** — operators with the wrong Go toolchain will get a build
failure that traces to the audit's number, not the codebase.

### 9. Untracked files (`git status`: `internal/core/arbitration.go`,
`internal/core/resolve.go`, `cmd/mpm-mcp/pidfile*.go`, `mpm-mcp`,
`mpm-mcp.pid`, `scheduler.lock`)

These look like in-progress work — investigate with the author before
committing. The new pidfile has good test coverage in `pidfile_test.go`
but the `pidfile_procname_*_*.go` non-Linux path has no tests.

## Final Assessment

The MPM codebase is **moderately production-ready** for a local-first
agent state system. The core data layer is small, well-tested, and uses
a single SQLite connection invariant that holds in practice. The main
risks are clustered around the **web/HTTP surface** (auth, CORS, CSRF,
frontend XSS) and **edge-case CLI flows** (backup/restore, shred,
fire-and-forget goroutines).

**Auto-fixes this pass (7 changes):**

1. C-1 fail-open web auth → fail-closed startup
2. L-15 malformed config → loud-fail at startup
3. H-13 config re-read → `sync.Once` cache
4. H-26 CORS wildcard → localhost-only echo
5. FE-XSS defensive CSP layer
6. L-26 silent test skip → `t.Fatalf`
7. H-22 10 MB memory → 1 MB per-memory content cap

**Operator action items (this PR):** none breaking. `make test` should
still be green; the existing `TestWithAuth_*` and `TestCSRF_*` tests
exercise the new startup contract.

**Follow-up work (next sprint):**

- C-2 restore-db SQL parser allow-list
- H-2 shred singleton reset refactor
- H-4 restore-db concurrent-daemon guard
