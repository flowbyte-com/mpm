All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.1.0] - 2026-06-19

> ### Reference arc complete
> 
> The reference pipeline is now end-to-end: ingest, chunk, diff, embed, search.
> Re-ingesting an unchanged manual costs zero embedding work — the load-bearing
> win of the chunk-hash diff.
> 
> ### Shelf-vs-Mind architecture
> 
> References are a shelf. They exist, are indexed, and are embedded for search.
> They are **not** memories and do not pass through the admission function at
> ingest time. Admission becomes a per-consult decision — triggered later when
> an agent extracts a pattern from a reference it has consulted. This was the
> architectural simplification that cut the original "admission tuning" scope
> from hours of work to a single sentence: the tuning axis is gone.
> 
> ### Highlights
> 
> - **Unified write surface**: `ReferenceDB` is gone. All reference writes go
>   through `DatabaseManager.WithTx` — no more split-brain trapdoor between two
>   write surfaces, no more "did this go through the watchdog telemetry?"
> - **Chunk-hash diff ingest**: `DatabaseManager.AddReference` now upserts and
>   applies a content-hash-keyed diff. Unchanged chunks are reused, updated
>   chunks have their embedding cleared (so re-embedding is forced), and
>   orphan chunks are deleted atomically.
> - **Embedding in a separate phase**: `DatabaseManager.EmbedReferenceChunks(ctx,
>   docID)` fills NULL embeddings after the chunk-insert tx has committed.
>   Embedding failures are best-effort; a follow-up pass fills the gaps. The
>   split keeps the ingest tx small and fast, makes embedding independently
>   retryable, and lets callers parallelize the embed pass without rewriting
>   the ingest path.
> - **Migrations are idempotent**: `reference_chunks` gained `content_hash` and
>   `embedding` columns via `SafeMigrations`. Existing DBs pick them up on
>   next boot; new DBs include them in `CREATE TABLE` from the start.
> - **In-memory test isolation**: a per-test shared-cache DSN pattern
>   (`file:ref_<hex>?mode=memory&cache=shared`) gives every test a private
>   in-memory SQLite owned by that test alone — no cross-contamination, no
>   tmpdir on disk.
>
